# AI 知识库类小程序：从 0 到上架通用流程手册

> 适用场景：你要做一个"AI 问答 / 智能学习伙伴 + 私有知识库"类的微信小程序，并把它发布上线。
> 本文不讲任何具体项目，只讲通用步骤、通用命令和通用坑。照此走完，约 1-2 周（含备案与审核等待）。

---

## 〇、先看全局：九个阶段

```
① 形态设计  →  ② 账号资质  →  ③ 项目初始化  →  ④ 知识库工程化
（AI走云端）   （备案最慢）    （技术选型）     （内容变私有API）
                                                      ↓
⑨ 发布运营  ←  ⑧ 上传提审  ←  ⑦ 测试门禁  ←  ⑤ 云函数开发  ←  ⑥ 客户端开发
（灰度+盯成本） （审核话术）   （自动化回归）   （模型密钥只在服务端） （云端优先+离线降级）
```

---

## 阶段一：形态设计（写代码前，先定 4 条规矩）

AI 类小程序先想清楚这几件事，后面不返工：

1. **AI 能力全部走云端**：模型 API Key 绝不放进客户端包（包会被反编译）。客户端 → 你自己的云函数 → 模型厂商。
2. **私有内容不进客户端包**：知识库原文只放服务端，客户端通过云函数接口按需拉取，包体也由此从 MB 级降到 200KB 内。
3. **关键判定不交给模型**：凡是"解锁、点亮、打分、通过"这类决定，用本地确定性规则；模型只负责讲解和生成内容。这样既可控，也好过审。
4. **必须有降级路径**：模型挂了、没网了，小程序核心流程仍然能用，界面上诚实标注"离线模式"。

## 阶段二：账号与资质（周期最长，最先启动）

| 事项 | 在哪办 | 周期 | 说明 |
| --- | --- | --- | --- |
| 注册小程序 | mp.weixin.qq.com | 当天 | 拿到 AppID |
| 小程序备案 | mp 后台 | 数天～2 周 | **不备案不能上架，第一天就提交** |
| 服务类目 | mp 后台 | 当天 | 提审时必须一致，教育/工具类较常见 |

| 微信开发者工具 | 官方下载 | 当天 | 稳定版 |

⚠️ **账号主体尽量统一**：小程序、云开发环境、支付（如有）用同一个微信号/主体开通。如果云环境买在另一个账号下，要在 CloudBase 控制台开「环境共享」授权给小程序账号，否则客户端永远调不通——这是最容易卡两三天的坑。

## 阶段三：技术选型与项目初始化

两条路线任选：

- **原生小程序 + TypeScript**（推荐用于中小项目）：无框架负担，审核兼容性最好。
- **Taro / uni-app**：需要同时出 H5/多端时再选。

初始化约定：

```
miniprogram/
  app.ts              # 入口：初始化云环境、后台预热数据
  config/             # 环境 ID、函数名等常量
  core/               # 纯逻辑层：内容、规则、返回解析（不碰 wx API，方便单测）
  services/           # 云调用封装、本地存储
  pages/              # 页面
cloudfunctions/       # 云函数
cloudbaserc.json      # 云函数配置（运行时/超时/环境变量占位）
scripts/              # 内容索引构建脚本
package.json          # test / lint / typecheck 脚本
```

三条目录纪律：页面只做展示和交互，业务规则放 `core/`（可单测）；所有云端返回都经解析函数校验字段；密钥永不进 `miniprogram/`。

## 阶段四：知识库工程化（把内容变成服务端私有 API）

通用流水线：

```
原始文档（Word/PDF/Markdown）
  → ① 构建脚本切分成 300~500 字的知识片段（chunk），打上标题/关键词
  → ② 输出结构化 JSON，随云函数包部署（不进客户端）
  → ③ 云函数提供「分页拉取」+「关键词检索」两个能力
  → ④ 客户端三级就绪：内存 → 本地缓存(storage) → 云端拉取 → 全失败用离线兜底内容
```

要点：切分脚本要**确定性**（同一份文档永远切出同样结果），不要用模型在线切；客户端至少准备几条自写的兜底内容，保证断网时核心流程不断。

## 阶段五：云函数开发（AI 的大脑）

典型函数组合：

| 函数 | 作用 | 建议超时 |
| --- | --- | --- |
| `healthCheck` | 健康检查，排查联通性问题 | 10s |
| 知识接口 | 分页拉取 / 检索知识片段 | 10s |
| AI 对话 | 检索相关知识 → 拼 prompt → 调模型 → 返回结构化 JSON | 60s |

AI 对话函数的通用模式（比"直接问模型"好用得多）：

1. 先用用户问题**检索知识库**，把命中片段塞进 prompt，要求模型基于依据回答（防胡说）。
2. 要求模型输出 **JSON**：`{answer, followUp, suggestions[]}`，客户端解析渲染"回答 + 追问 + 建议问题 chips"。
3. 进阶：让模型输出**行动协议**（"我要查知识库 / 我要看目录 / 我现在回答"），云函数循环执行——这就是最小可用的 Agent。
4. 模型调用**失败自动重试一次**；再失败返回 `mode:"fallback"`，客户端降级。
5. 每次模型调用约 5-7 秒，加上冷启动，用户等待可能 10 秒以上——客户端必须配**超时兜底**（如 20 秒无响应自动切本地回答），不能无限转圈。

### 部署与验证（tcb CLI，别用开发者工具的云面板）

```bash
# 安装：npm i -g @cloudbase/cli，之后建议用绝对路径调用（npx 会卡交互确认）
tcb login                                    # 浏览器授权；凭据会过期，过期重跑
tcb fn deploy <函数名> -e <环境ID> --force      # 部署
tcb fn invoke <函数名> -e <环境ID> --params '{"question":"测试问题"}'   # 远程实测
```

⚠️ **环境变量覆盖坑**：`deploy --force` 会用 `cloudbaserc.json` 里的 `envVariables` **整体覆盖**云端已配置的变量。文件里密钥写成 `{{env.XXX_API_KEY}}` 占位符，部署时在命令行内联真实值：

```bash
XXX_API_KEY=sk-真实key tcb fn deploy aiChat -e <环境ID> --force
```

⚠️ `tcb fn log` 已废弃，查行为用 `fn invoke` 实测 + 控制台日志。

## 阶段六：客户端开发

1. **调用模式**：云端优先 → 超时/失败 → 本地降级，每种结果在 UI 上标注来源（"云端回复"/"离线模式"），用户知情、审核也好看。
2. **状态存储**：用户进度等非敏感状态用 `wx.setStorageSync` 本地仓储即可，早期不必上账号体系。
3. **体验细节**：等待时给打字/思考动效；AI 回复附"建议问题"降低用户输入成本；首次达成给庆祝动效。
4. **新手引导**：首次启动的引导层用 `wx.hideTabBar()` 强制走完，选完偏好再 `showTabBar()`。
5. Canvas 绘图记得乘 `dpr` 缩放，否则高分屏画面缩在角落。

## 阶段七：测试与质量门禁（每次上传前跑一遍）

```bash
npm test                 # 单元测试：core/ 纯逻辑全覆盖
npm run lint             # 静态检查零警告
npm run typecheck        # 严格 TypeScript
# WXSS 用开发者工具自带编译器校验：
/Applications/wechatwebdevtools.app/Contents/Resources/app.asar.unpacked/node_modules/wcc-exec/wcsc -cpp <file.wxss>
```

模拟器自动化回归（不用肉眼点点点）：

```bash
# miniprogram-automator 装在项目目录之外，避免污染依赖
/Applications/wechatwebdevtools.app/Contents/MacOS/cli auto --project <项目路径> --auto-port 9421
# 脚本连接后可：遍历页面收集 console 报错、callMethod 模拟用户操作、截图存档
```

## 阶段八：上传与提审

```bash
# 上传开发版本（纯命令行，不用打开 IDE 界面）
/Applications/wechatwebdevtools.app/Contents/MacOS/cli upload \
  --project <项目路径> -v 1.0.0 -d "本次改动说明"
```

然后到 mp.weixin.qq.com → 管理 → 版本管理 → 开发版本 → **提交审核**：

- 类目与备案一致；功能页面填首页路径。
- **AI 类小程序的审核备注模板**（实测好用）：

  > 本小程序为 XX 领域学习/问答工具。AI 回答由服务端调用已完成备案的大模型生成，内容基于服务端私有知识库，仅用于学习辅导；用户内容不对外展示；关键判定由本地规则完成，非模型生成。测试路径：XX Tab → 输入"一个示例问题"。

- 隐私协议：mp 后台 → 设置 → 服务内容声明 → 用户隐私保护指引，按实际收集情况如实勾选（如有文件上传功能必须声明）。
- 审核通常 1 天内出结果；通过后点「发布」即上线。

## 阶段九：发布与运营

1. 正式发布前，先用**体验版二维码**找 3-5 个真实用户完整走一遍核心流程。
2. 盯两件事：**模型 API 调用量与费用**、云函数报错日志（控制台 + `tcb fn invoke` 定期实测）。
3. 想让用户能转发，记得在页面里配置 `onShareAppMessage` / `onShareTimeline`（不配就没有分享入口）。
4. 迭代节奏：改代码 → 质量门禁 → 部署函数 + invoke 实测 → 自动化回归 → cli upload → 提审 → 发布。

## 附一：通用坑清单（每条都值半天）

1. **跨账号调不通**：云环境与小程序不同主体时必须开「环境共享」；开发者工具扫码登录时看清登的是哪个微信号。
2. **IDE 里绑定云环境会写坏配置**：`project.private.config.json` 的 `cloudfunctionRoot` 被写成对象数组后，模拟器全页面编译 500 白屏（CLI 上传不受影响）。改回字符串 `"cloudfunctions/"`，之后别再点 IDE 里的绑定按钮。
3. **部署覆盖密钥**：见阶段五，密钥永远内联传。
4. **npx 卡交互**：脚本里调用 CLI 一律用绝对路径。
5. **代理残留**：本机开过 Clash/VPN 后 `cli upload` 可能 ECONNRESET，重启开发者工具主进程（它缓存启动时的代理）。
6. **缓存幻觉**：排查诡异问题先清开发者工具缓存再编译。
7. **模型抖动**：模型 API 会偶发 5xx 和慢响应——重试一次 + 客户端超时兜底 + 降级路径，三件套缺一不可。
8. **WXML 限制**：不支持 `{'\n'}` 等插值表达式，会原样显示；生僻 emoji 部分机型异常。
9. **fixed 弹层被压**：全局样式里给容器子元素设 `position:relative; z-index` 的规则会盖住 fixed 遮罩，弹层 DOM 要放到容器外。
10. **备案与审核是串行最长路径**：第一天就提交备案；提审备注写清"模型已备案、内容私有、判定本地"，一次过的概率高很多。
